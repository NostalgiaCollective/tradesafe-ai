# Fast, reliable electrical workspace

The electrical job no longer waits for closed evidence and revision panels. Opening either panel loads bounded records through the same authenticated site access checks. The core job and company membership reads run together. The page reuses its authenticated request context; it does not cache users, records or permissions across requests.

The initial local trace fell from 14 to 12 Supabase requests. The earlier code called the authentication helper twice, but Next already deduplicated the underlying auth request in these samples. The two removed requests are the evidence and revision queries. Action counts already use exact HEAD queries, and linked report/brief lists already have eight-record limits; those rules remain unchanged. No index, cache, infrastructure or migration was added.

Local warm electrical loads were 1,721 and 1,335 ms before, and 1,163 and 1,260 ms after. These small samples include Next development overhead and network variability. First loads and hosted measurements are recorded separately. The authorized company list grew as synthetic tests created fixtures, so total payload sizes are not a controlled before/after comparison. A matched populated hosted fixture is used for the delivery comparison. The trace contains paths, status, timings and byte counts only, never headers or record contents.

## Save defect

An idempotent replay returns the original successful result. If a second editor saved afterward, the UI previously treated that older result as current. The new browser regression reproduces the lost response, records a second editor's change, then retries the first request. It fails on the old code because there is no conflict warning.

The editor now reads the authoritative revision before confirming a save. A newer revision keeps the entered text and opens a comparison. **Keep my entries for review** changes the editing baseline only; it neither merges nor submits. **Use server entries** asks before discarding local text. A subsequent save still uses the server's revision check. A network or session failure retains the original request ID and payload. The extra confirmation read adds latency to saving; this is a reliability tradeoff, not a save-speed improvement. It confirms the revision at read time, not an everlasting lock on the job.

## Loading and scope

**Refresh saved work** refreshes authorized links and counts without replacing the electrical form. Failed refreshes label the previous results as stale. They never turn failure into zero outstanding work. Returning focus marks those results as potentially changed without background polling. A failed evidence/history request has its own retry and preserves selected references.

Independent documentation, internal review, ESA and evidence statuses still describe the saved electrical revision. Current follow-up counts remain site-scoped, including concerns; workers see assigned follow-up. Electrical exports remain byte-for-byte generated by the unchanged retained-revision formatter. Current Actions and Daily handover are separate records with separate scopes.
