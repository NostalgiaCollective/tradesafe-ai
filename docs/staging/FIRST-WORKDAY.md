# First workday and private pilot feedback

Staging-only Help and feedback extends company selection, pending invitations and the existing site workflow. Your first workday on Today is dismissible per authenticated account/company; Help always offers it again. Completion indicators use authorized saved records, not clicks. Site availability is not assignment. Missing briefing participation or assigned actions is explicitly explained. Revoked access uses the existing denial page; no link grants membership.

Company owners manage privately submitted feedback. Workers and supervisors see only their own submissions; active owners see their company's list. Statuses are received, investigating and resolved, with immutable submission text and actor/time status history. Status updates require a matching revision. Duplicate retries use a company/request/actor receipt. Ten submissions per account per hour; bounded text and 20-row pagination. No notification, external tracking, attachments or automatic content capture. Technical context is a pathname without query/fragment, served version, server timestamp and UUID support reference. User-entered feedback should exclude secrets and report content.

Practice uses a separately designated company with existing membership rules and separately authenticated synthetic accounts. No automatic worker acknowledgement occurs. Counts always remain company scoped. A practice company cannot be converted back into an operational company. Database guards preserve PRACTICE labels in company/site names, which flow into existing historical snapshots and exports. Designation is allowed only before a company's first site/report/brief; existing records are never relabelled. The generic recording workflows and qualified-review limitations are unchanged.

Run `node --use-system-ca scripts/staging/prepare-first-workday.mjs` after the new additive migration is applied to the verified staging project. It reuses prepared synthetic accounts, stores stable IDs and invitation requests in ignored `.staging/first-workday-practice-private.json`, and does not reset data. Rerunning reuses the same company/site. Credentials never enter Help, exports or logs. A revoked practice membership needs deliberate coordinator review; the helper is not an invitation to restore arbitrary access.

Human scenario: sign in separately as the prepared supervisor and worker; select the practice company; follow Help → Practice a workday. Supervisor records a site brief including the worker. Worker acknowledges the displayed version and reports a synthetic concern. Supervisor assigns it and its deadline; worker requests verification; supervisor verifies and closes. Return to the site for history, handover and evidence package. Submit a Problem or Suggestion through Help; the prepared owner can manage its status. This is rehearsal data, not safety certification or human usability acceptance.

Exact CI, hosted results, fixture locations and remaining limitations belong in the durable checkpoint and `.staging/first-workday-delivery.md`. Previously deferred domain/email, qualified content review, privacy/operations and hosted recovery gates remain open. No production-readiness claim.
