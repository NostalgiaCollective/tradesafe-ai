## Supported invitation-only route

Use existing app-created **company** invitations with the intended email/role and manually copied authenticated link. This is different from Supabase's **Invite user** email. A current verified user signs in and accepts; wrong-account, expired/revoked and already-accepted states retain existing checks. The inviter verifies active membership and the intended site access. Links do not confer unrelated access.

For a genuinely new external user, use the supported email/password confirmation flow only after sender and that recipient/test are authorized, then accept the company invitation. Do not auto-confirm customers, share synthetic credentials, create aliases to evade Resend, weaken email checks or reset existing accounts. The pilot can be invitation-only even though invited users establish an account through a confirmation page. A public self-service marketing/signup launch is not required.

Recovery remains a separate entry test. The staged app dispatch requires both `RECOVERY_EMAIL_ENABLED=yes` and an allowed recipient. Propose a finite approved pilot-recipient list, not removal of the allowlist. The current SMTP and public URLs were inspected read-only on October 10; the current Render secret/allowlist values still need private operator comparison against `.staging/server.env` before any change. There were no email deliveries in this preparation.
