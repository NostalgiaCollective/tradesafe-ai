## Prepared implementation and local checks

`render.yaml` is a reviewable specification, not an applied deployment. `scripts/staging/prepare-hosted.mjs` prepares private `.staging/hosted.env` and `.staging/hosted-access.json` without networking, overwrites or publication. The latter also retains a planned phone-test password, not yet used. The two new staging endpoints are unavailable in ordinary non-hosted mode. Build and startup commands are `npm run staging:hosted:build` and `npm run staging:hosted:start`.

`hosted-server.mjs` starts Next with **`dev: false`** and a canonical external hostname/port distinct from Render's listening port. The access gate runs before Next routing, including static resources. The original application proxy remains unchanged. Build output is isolated in `.next-hosted`, and a private, authenticated identity endpoint reports commit, project reference, canonical origin and public-key digest; startup refuses build/runtime mismatches. The original local development server is never publicly exposed.

`node scripts/staging/hosted-local.mjs` builds and exercises the production launcher bound explicitly to **127.0.0.1:3108**, simulating the hosting proxy headers. Seven groups passed: production build, client secret audit, minimal health, whole-site access challenge, exact build/project/origin identity, private-route and recovery-grant denial, and origin/checkout denial. Initial failed preflights are timestamped and preserved. The harness now sends an explicit Host header through Node HTTP rather than assuming `fetch` preserves it. No public URL, real TLS edge, Linux deployment or physical device is claimed by these checks.

Installed Supabase SSR defaults did not explicitly set `Secure` on ordinary sign-in cookies. Browser/server/refresh adapters now set it whenever the canonical app URL is HTTPS. Recovery already uses its separate Secure/HttpOnly/SameSite=Strict cookie. Ordinary SSR cookies remain browser-readable as required by the SDK; this change does not claim HttpOnly ordinary sessions. The targeted local HTTPS regression passed with the existing dedicated account: ordinary cookies were Secure/SameSite=Lax, and authorized photo/PDF hashes were unchanged. No email or password change occurred; `.staging/hosted-cookie-regression.json` records its timestamp and provenance.

The complete local suite has 37 tests, including hosted isolation/perimeter failures and existing auth/membership/evidence/PDF tests. Keep build, typecheck, lint and smoke results in the durable checkpoint. Do not count compiled `.next-hosted` artifacts as source lint inputs.
